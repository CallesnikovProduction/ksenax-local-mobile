# AGENTS.md

## Версия разработки

Текущая ветка разработки — **OpenKsenax 0.3**. Версия 0.2 считается
зафиксированным историческим срезом. Любая новая KDoc-документация, публичный
контракт и спецификация, добавленные в этой версии, обязаны содержать отметку
`@since 0.3`. Старые комментарии и исторические `@since 0.2` не переписываются
только ради смены версии.

## Назначение core

Core OpenKsenax — local-first Android-основание приложения. В него входят:

- жизненный цикл и конфигурация локальных model runtime;
- загрузка, проверка целостности и подготовка моделей;
- orchestration, tool routing и контролируемое выполнение Android-действий;
- хранение чатов, настроек и runtime-состояния;
- основной UI, темы, голосовой ввод и системные разрешения.

Ветка `core-0.3` намеренно не содержит addon-контракт, каталог, discovery,
registry, coordination, model-provider IPC и addon presentation. Эти контуры
разрабатываются отдельным вертикальным срезом и подключаются только вместе со
своими Gradle-зависимостями, Manifest-компонентами и composition-root wiring.

## Архитектурные границы

- Один process-level composition root принадлежит `KsenaxAndroidApplication`.
- Model runtime не знает о UI, PackageManager, HTTP, installer и policy.
- Download-контур передаёт только проверенный путь к установленной модели.
- Presentation не выполняет файловый, сетевой или PackageManager IO напрямую.
- Android `Context` не передаётся в domain-модели.
- DTO внешних источников, domain-модели и UI state не смешиваются.
- Сетевой, файловый и PackageManager IO не выполняется на main thread.
- Отмена coroutine не превращается в обычную ошибку.
- Отсутствие модели, файла или разрешения означает явный fail-closed результат.
- Глобальное изменяемое singleton-состояние не используется.

## Правила изменения кода

- Перед изменением читать ближайший `AGENTS.md` и существующие паттерны пакета.
- Не создавать второй downloader, parser, storage или composition root без
  отдельной архитектурной причины.
- Новый интерфейс добавлять только для реальной границы, внешнего API,
  нескольких реализаций или изоляции Android/framework-зависимости.
- Не создавать God class и не дробить одну ответственность на формальные
  классы без самостоятельного поведения.
- Не ловить `Throwable` без повторного проброса `CancellationException`.
- Не возвращать фиктивный успех и не оставлять молча работающие заглушки.
- Существующие public API не ломать без необходимости и описанной миграции.
- Публичные архитектурные типы документировать KDoc с `@since 0.3`.

## Проверка результата

Минимальная проверка core-изменений:

```powershell
.\gradlew.bat compileDebugKotlin
.\gradlew.bat testDebugUnitTest
.\gradlew.bat assembleDebug
```

Изменения model runtime, Android lifecycle, фоновой финализации загрузок и
разрешений дополнительно требуют проверки на реальном устройстве. Успешная JVM-
сборка не доказывает корректность process death, WorkManager, DownloadManager
receiver или native LiteRT inference.
