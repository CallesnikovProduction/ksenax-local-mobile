# Узкие промпты FunctionGemma

Автор: Stephan Kolesnikov. Версия: 0.4. Проверка: 9 октября 2026.

42 реальных вызова на HONOR ELI-NX9, LiteRT-LM 0.13.1, CPU,
контекст 1024, greedy. Каждая команда получает новую Conversation через
рабочий `askFunctions`; native function-call проверяется без исправления ответа.
G4 и Android-executors не вызывались. Установлен только тестовый APK,
рабочее приложение, модели и его промпты не заменены.

FG: `openksenax_functiongemma_270m_mobile_actions_q8_ekv1024.litertlm`.
SHA-256 на телефоне:
`92109695f911d1872fa8ae07c1e3ff0ed70f2c3d1690d410ec6db8587c2ab409`.

## Результаты

| Прогон | Схема | Точный маршрут и действие |
| --- | --- | --- |
| `fg-narrow-torch12-20261009-v1` | Рабочий полный каталог | 1/4 |
| тот же | Только фонарик и три неисполняемых маршрута | 3/4 |
| тот же | Узкий каталог с усиленными инструкциями | 2/4 |
| `fg-narrow-state20-20261009-v2` | Узкий каталог, расширенный корпус | 5/10 |
| тот же | Одна функция `set_flashlight_state(state: on/off/toggle)` | 5/10 |
| `fg-narrow-russian10-20261009-v3` | Состояние, русские описания и правила | 4/10 |

Первый корпус: включение, зажигание, выключение и гашение фонаря.
Расширенный добавляет другую формулировку выключения, вспышку, вопрос,
отрицание, заметку и смешанный запрос. Ожидания не участвуют в промпте.
Преобразование модельного enum в имя действия не анализирует UP.

- Узкий каталог исправил `Выключи фонарик`: `torch_off`, вместо `torch_on`
  полного каталога. Но `Погаси фонарь` возвращает `route_unsupported`.
- Английская схема состояния отклоняет информационный вопрос корректно,
  но `Не зажигай фонарик` ошибочно получает `state: off`.
- Русская схема исправляет отрицание, но отклоняет обычное выключение и заметку.
- Смешанный запрос в расширенных вариантах даёт несколько calls и отклоняется.

Измеренное полное время одной проверки в расширенных сериях — примерно
3,5–4,1 с; это не только decode. В JSONL отдельно сохранены `latencyMs`
модельного ответа и `wallLatencyMs` проверки.
Сам `askFunctions` сообщает 0,50–0,97 с для английских расширенных схем
и 0,80–1,19 с для русской; создание Conversation не входит в этот показатель.

## Граница вывода

FAIL для внедрения. Более узкий промпт помогает отдельным командам, но
устойчивость семантики не доказана. Семейство фонарика заранее ограничено
экспериментом: это не проверка автоматического выбора семейства. Будильники,
календарь, toggle, полный корпус, повторы стабильности и физическое исполнение
новых схем не проверялись. Это не доказательство невозможности улучшить FG.

Сборки тестового APK и `git diff --check` прошли. `OK (1 test)` означает
завершение измерений, а не успешность ответов модели. Последний тестовый APK:
`4DCCC0369946255F74191A3A2899221376DB4068839BEF4F9E5AA43B54F2D7F9`.
Полные запросы, declarations и native calls сохранены в JSONL указанных
прогонов в `app/build/reports/live-routing/` и внешнем `files/live-routing`
приложения. Изменения только в диагностике; commit/push не выполнялись.
Независимый review подтвердил отсутствие ожидаемых ответов в промпте,
строгую оценку enum и отсутствие подмены выбора Kotlin-правилами.
